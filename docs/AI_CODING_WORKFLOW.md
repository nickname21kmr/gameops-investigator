# 一次真实的 AI 辅助修复：证据不足时停止归因

日期：2026-09-20。审查基线：`89f40a7bc59021b923bdc1285846888d4987c875`。

这份记录描述本次实际发生的工作，不补写为项目最初开发时就存在的流程。项目负责人提出 GitHub 审查需求，并选择优先修复 GameOps 的问题；Codex 执行代码检查、反例复现、实现、测试和文档整理，多名 Codex 子代理分别处理 SQL、反例测试、界面与失败路径复核。代码审查是 AI 交叉审查，不能替代项目负责人的理解或人工验收。没有把这些代码改动描述为负责人逐行手写。

## 需求与选择

使用场景是分析人员查看游戏指标告警、对比玩家分群并复核证据。目前仓库提供的是合成数据上的可运行演示，没有真实商业用户或生产收益的证明。

本次优先解决结果可信度：程序在数据不存在时仍支持预设原因，或者把事件数当作人数，都会直接误导调查。选择保留现有轻量工作台、CLI 和 MCP 接口，修改共享的统计与协调逻辑，让修复覆盖各个入口；没有新增平台层或更多 Agent 框架。CLI/MCP 可以独立调用，工作台用于并排查看图表、SQL 和证据。

验收条件：

1. 两个窗口为空、样本不足、关键证据缺失、方向相反、变化不显著或工具失败时，不输出受支持的原因。
2. 三个原有事故仍能找到对应候选，并保留可核对的引用。
3. 同一个玩家新增事件，不改变 cohort 的人数；没有事件的玩家仍计入人数。
4. 界面与报告导出能展示空候选；失败诊断中的私有路径不进入调查导出。
5. 评测不能因预设 ID 出现在 alternative 中就算归因成功。

## 复现与定位

| 问题 | 可重复触发方式 | 修复位置 |
| --- | --- | --- |
| 无数据仍支持预设原因 | 在内存中把场景日期及证据 SQL 改到 2099 年，保留真实数据库读取 | `orchestrator.py`：先验证证据，达标后才构造候选 |
| JOIN 放大人数 | 临时 SQLite 中放 3 名玩家，每人 28 条事件，原查询会数到 84 | `config/scenarios.json`：`COUNT(DISTINCT u.user_id)` |
| 基线太小也列为异常 | 构造统计显著但任一窗口未达门槛的真实 SQLite cohort | `detector.py`：检查两个窗口 |
| 工具失败诊断进入导出 | 缺失数据库路径、工具返回错误、报告工具抛出异常 | `_call`：统一失败结果，保留失败状态，剥离原始诊断 |
| 评测误把列出答案视为支持答案 | 失败调查、无支持状态、只含 alternative 的预期 ID | `evals/run_evals.py`：同时检查运行、调查与候选状态 |

候选反例测试先在原实现上出现 31 项失败：27 项仍错误给出支持候选，3 项正常事故缺少新的状态字段，1 项工具异常未被处理。另补的 3 项采用率交叉检查未单独执行旧实现红测。SQL 的五项测试在修复前为 3 项失败、2 项通过。失败诊断与评测各自也执行了修复前反例，不把“新增测试通过”当作已证明抓到旧错误。

## AI 工作流与审查发现

1. **明确边界**：读取现有代码、数据声明与工具契约；本次只验证确定性回放，不调用付费模型来充当测试结果。
2. **并行分工**：SQL 修复与 SQL 反例由一个子代理处理；候选门槛的反例测试由另一个子代理独立编写；主代理实现状态与报告传播；第三个子代理检查界面和批量报告。
3. **反例驱动实现**：先运行空窗口、同窗口、反向窗口、低样本等情形，再保留三个正常事故作正向对照。不是仅检查代码里出现了某个字段。
4. **交叉审查**：复核发现仅捕获异常仍会漏掉 `ok: false` 返回中的私有诊断；检测器只检查当前窗口；重复上报的推理缺少直接引用；medium 被无条件升为 high。对应修复和回归测试随后加入。
5. **契约对照**：工作台、CLI、报告 Markdown/JSON、离线评测使用一致状态；候选仍是关联解释，不声称自动找到了业务根因。
6. **最终验证**：运行自动化测试、40 条离线评测、重新生成三个报告、审计轨迹，并核对源数据校验和。实际验证结果见本文件下方的验证记录及对应提交的 CI。

这次用了主代理与子代理的任务分工；没有证据表明开发时使用了某个专用需求 Skill、自动生成过正式 PRD/AC 文档，或对 Codex、Claude Code、Copilot 做过同题对比。不能从这份记录推出这些经历。
